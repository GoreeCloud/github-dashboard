## Application mapping

### Presentation and authority

Glaze UI remains presentation-only. Dashboard state continues to come from GitHub or the applicable GoreeCloud producer. The interface does not infer authorization, policy approval, health, freshness, privacy, security, recoverability, or conformance merely from visual state. Unknown or unavailable producer evidence remains visibly unresolved.

### Material hierarchy

- **Canvas:** restrained Deep Teal / Soft Amber application atmosphere.
- **Surface:** durable panels, cards, tables, timelines, and data-reading regions; these remain solid or near-solid and never require backdrop blur for comprehension.
- **Glaze:** bounded active navigation and shell material for the current form factor.
- **Higher optical richness:** optional only when it improves hierarchy without weakening accessibility, performance, or state truth.

The current application layer is public/glaze-v1.6.css. V1.6 does not require the dashboard to duplicate the complete Glaze UI repository; it adopts the shared target through an application-specific mapping while preserving the shared authority boundary and inherited stable visual material baseline.

### Appearance

The source exposes four deterministic appearance states: **System**, **Light**, **Dark**, and **Deep Dark**. The control cycles System → Light → Dark → Deep Dark → System, persists only the user's selected appearance when browser storage is available, and fails soft when storage is unavailable.

### Input, navigation, and continuity

Touch-capable controls retain a 48 px minimum reference target. Keyboard focus stays visible. Hover remains supplementary. Phone uses reachable bottom navigation, Tablet uses a full-label horizontal navigation composition, Desktop uses a persistent sidebar, and Wide Desktop increases information density without unbounded line length.

Navigation and search presentation must remain stable as asynchronous repository evidence arrives. Glaze presentation must not auto-navigate, auto-authorize, or execute consequential fallback behavior.

### Accessibility and resilience

Source behavior retains skip navigation, visible focus, Reduced Motion, Reduced Transparency, Increased Contrast, Forced Colors, solid material fallbacks, and horizontal overflow for dense tables. Accessibility has presentation precedence over decorative richness. Stale, partial, unavailable, blocked, and error states must remain understandable without depending on color, blur, motion, or hover alone.

### Performance and diagnostics

V1.6 adds a stronger shared performance/diagnostics boundary, but shared-library qualification is not downstream performance acceptance. The dashboard still requires repository-local representative performance evidence. Diagnostics remain privacy-minimized and must not include raw sensitive context or credential material.
